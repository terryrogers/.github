# Contributing

Thank you for improving repositories maintained by **terryrogers**.

## Before You Begin

Read the target repository's README, licence, support guidance, security policy, & any local contribution instructions. A local file overrides this account default.

Use [GitHub Discussions Q&A](https://github.com/terryrogers/.github/discussions/categories/q-a) for support or design questions. Use an issue for a reproducible defect or a scoped feature request. Do not disclose vulnerabilities publicly; follow `SECURITY.md`.

## Development Setup

Use the setup, dependency, build, test, formatting, & validation commands documented by the target repository. If those commands are missing or unclear, open a discussion before making a large change. This central file does not invent project-specific commands.

## Contribution Workflow

1. Keep each change focused & explain the user-visible outcome.
2. Use a short-lived branch when a branch is required.
3. Add or update meaningful tests for changed behavior.
4. Run the repository's documented formatting, tests, security checks, & build.
5. Update public documentation & changelog entries when users are affected.
6. Open a pull request using the supplied template.

## Review Expectations

Reviewers may request changes for correctness, tests, compatibility, accessibility, security, privacy, documentation, or maintainability. Do not include credentials, personal data, private paths, internal systems, or private project-management identifiers.
